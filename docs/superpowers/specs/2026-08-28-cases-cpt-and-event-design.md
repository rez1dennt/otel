# Семь кейсов, нативный шаблон WordPress и ближайшее мероприятие

Дата: 28 августа 2026 года  
Статус: выбран первый вариант — нативный тип записи WordPress без ACF; требуется просмотр письменной спецификации перед планом реализации

## 1. Цель

Добавить на статический сайт семь подтверждённых кейсов Виталины Погорилы, заменить демонстрационный кейс реальным содержанием и обновить ближайшее мероприятие по официальной странице «Коммерсанта».

В WordPress-теме кейсы становятся отдельным типом записи. После установки темы администратор сможет добавлять новые кейсы по тому же шаблону без ACF и других внешних плагинов. Текущая HTML/CSS/JavaScript-версия остаётся рабочей и не удаляется.

## 2. Источники и редакционные границы

### Кейсы

Единственный источник фактов о семи проектах — материалы Виталины, переданные заказчиком 27 августа 2026 года. Редактура исправляет орфографию, пунктуацию, типографику и тяжёлые конструкции, но не меняет:

- тип объекта;
- номерной фонд;
- расположение;
- выполненные действия;
- сроки;
- финансовые и операционные показатели;
- вывод кейса.

Названия отелей не придуманы и не раскрываются. Используются только переданные описания: «загородный отель», «городской отель», «премиальный загородный отель», «экоотель». Формулировка «простойный период» исправляется на «период простоя», «обьект» — на «объект». Англоязычные отраслевые сокращения при первом упоминании получают краткое пояснение.

## 3. Информационная архитектура кейсов

### Архив

Адрес `/kejsy/` сохраняется. На странице выводятся семь карточек в порядке кейсов № 1–7. Карточка содержит:

- иллюстрацию;
- тип объекта или краткую метку;
- заголовок;
- одно предложение о задаче;
- две–три основные метрики;
- действие «Смотреть кейс».

На главной странице показываются три кейса, которые демонстрируют разные типы работы:

1. «Перезагрузка загородного отеля»;
2. «Пересборка маркетинга городского отеля»;
3. «Перепозиционирование экоотеля через аутентичность и контент».

После карточек на главной размещается ссылка «Смотреть все кейсы» на `/kejsy/`.

### Детальная страница

Все семь страниц используют одну структуру:

1. Hero: метка «Кейс», заголовок, краткий лид и основные метрики.
2. Факты: объект, продукт, расположение и формат — только если поле заполнено.
3. Контекст: исходная ситуация без дублирования задачи.
4. Задача: проблема или ограничение, которое требовало решения.
5. Что сделали: нумерованные шаги с коротким названием и пояснением.
6. Результат: карточки подтверждённых показателей и краткая связка с выполненной работой.
7. Вывод: один содержательный абзац без рекламного самовосхваления.
8. CTA: «Обсудить задачу отеля» с открытием текущей формы заявки.

Пустые поля не создают пустых заголовков или больших отступов. На мобильных экранах заголовки, текст и метрики выравниваются по левому краю.

## 5. Единый источник начального контента

Начальные данные семи кейсов хранятся в `content/cases.json`. Это источник для:

- генерации статического архива и семи детальных HTML-страниц;
- трёх карточек на статической главной;
- начального наполнения WordPress после активации темы;
- проверок маршрутов, обязательных полей и метрик.

При сборке темы файл копируется в `wordpress-theme/forma-hotel/inc/data/cases.json`. После импорта WordPress-база становится источником опубликованных данных для WordPress-версии. Следующие сборки и повторная активация темы не перезаписывают изменения администратора.

Каждая запись JSON содержит стабильный `seed_id`, slug, заголовок, excerpt, факты, context, task, steps, metrics, conclusion, fallback image, порядок и признак показа на главной. Денежные значения и проценты хранятся как готовый текст, чтобы не потерять знак, единицу и основание сравнения.

## 6. Нативная модель WordPress

### Тип записи

Тема регистрирует `forma_case`:

- публичный тип записи с русскими подписями «Кейсы» и «Кейс»;
- `has_archive => false`, чтобы не конфликтовать со страницей `/kejsy/`;
- rewrite base `kejsy` для детальных страниц;
- поддержка заголовка, краткого описания, изображения записи, ревизий и порядка;
- REST API включён для совместимости с современным редактором;
- публичный query доступен, но отдельный архив CPT не создаётся.

Страница `/kejsy/` остаётся WordPress Page. Её `page-kejsy.php` запрашивает опубликованные `forma_case` по `menu_order`. Главная запрашивает три записи с рангом 1–3. Детальную страницу выводит `single-forma_case.php`.

Общие части:

- `template-parts/case-card.php` — карточка архива и главной;
- `template-parts/case-facts.php` — факты;
- `template-parts/case-metrics.php` — метрики;
- `template-parts/home-cases.php` — динамический блок главной.

Генератор темы не перезаписывает динамические шаблоны кейсов. Он продолжает синхронизировать остальные страницы и assets.

### Поля в админке

Стандартные поля WordPress:

- название кейса;
- краткое описание для карточки и SEO description;
- изображение записи;
- slug;
- статус публикации;
- порядок.

Нативный метабокс «Данные кейса»:

- тип объекта;
- продукт;
- расположение;
- формат;
- контекст;
- задача;
- вывод;
- режим публикации: публичный, анонимный объект, скрытые метрики;
- ранг на главной: 1–3 или «не показывать».

Метабокс «Что сделали» хранит от 1 до 8 строк. У каждой строки есть короткий заголовок и пояснение. Кнопки называются «Добавить шаг» и «Удалить шаг».

Метабокс «Результаты» хранит от 1 до 6 показателей. У каждого показателя есть значение и подпись. Кнопки называются «Добавить показатель» и «Удалить показатель».

Повторяемые поля используют нативный JavaScript админки, работают с клавиатуры и не требуют внешней библиотеки. Удаление строки не должно удалять весь кейс или сбрасывать другие поля.

### Сохранение и безопасность

Сохранение метаданных:

- проверяет nonce и право `edit_post`;
- пропускает autosave и неподходящие типы записей;
- очищает однострочные поля через `sanitize_text_field()`;
- очищает многострочный текст через `wp_kses_post()` с ограниченным набором безопасной разметки;
- нормализует массивы шагов и метрик, удаляя полностью пустые строки;
- экранирует каждый вывод по контексту;
- не принимает произвольный URL изображения в метаполе — используется Featured Image.

### Начальное наполнение

При активации тема импортирует семь кейсов идемпотентно:

1. Ищет запись по стабильному `seed_id`, затем по slug.
2. Создаёт запись только если совпадение не найдено.
3. Заполняет метаполя, порядок и fallback image только при первом создании.
4. Не перезаписывает текст, slug, изображение или статус существующей записи.
5. Повторная активация не создаёт дубликаты.
6. Ошибки импорта сохраняются в результате bootstrap и показываются администратору.
7. После регистрации типа записи и первого импорта rewrite rules обновляются один раз.

Удаление или деактивация темы не удаляет кейсы.

## 9. SEO и структурированные данные

### Кейсы

Каждая детальная страница получает:

- уникальные title и description;
- canonical на свой чистый URL;
- Open Graph с заголовком, excerpt и изображением;
- `BreadcrumbList`;
- `Article` с автором `Person` — Виталина Погорила, датой публикации записи и датой изменения;
- индексируемый URL в sitemap.

Архив `/kejsy/` получает `CollectionPage` и `ItemList` со ссылками на семь опубликованных кейсов. Черновики и записи в корзине не попадают в карточки, JSON-LD или sitemap.

### Мероприятие

Страница получает `Event` JSON-LD:

- `name`: «Индустрия гостеприимства»;
- `startDate`: `2026-09-10` без выдуманного времени;
- `eventStatus`: `EventScheduled`;
- `eventAttendanceMode`: `OfflineEventAttendanceMode`;
- `location`: бизнес-центр «Алкон III», Москва, Ленинградский проспект, 34А;
- `url`: официальный адрес мероприятия;
- `performer`: `Person` Виталина Погорила с подтверждённой должностью.

`endDate`, `offers`, `price` и расписание не выводятся без подтверждённых данных. Также добавляются `BreadcrumbList`, canonical и Open Graph.

## 10. Визуальные и адаптивные правила

Новые страницы продолжают действующую дизайн-систему: те же контейнеры, шрифты, цвета, радиусы, кнопки и ритм секций. Новый отдельный визуальный стиль не вводится.

Обязательные правила:

- fixed header всегда закреплён сверху и не меняет геометрию при открытии burger;
- burger открывается плавно, без резкого скачка и смещения контента;
- якоря и начало hero учитывают фактическую высоту header;
- на ширинах 320, 360, 768 и 1280 px нет горизонтальной прокрутки;
- мобильные заголовки и основной текст выровнены по левому краю;
- кнопки не прижаты к тексту и не выходят за карточку;
- карточки одной строки имеют согласованную высоту, а действия расположены предсказуемо;
- секции не создают гигантских пустых промежутков;
- метрики переносятся в одну колонку на узких экранах;
- изображения заполняют предусмотренную область без искажения;
- focus-visible заметен на ссылках, кнопках и элементах админки;
- анимации учитывают `prefers-reduced-motion`.

## 11. Ошибки и пустые состояния

- Если опубликованных кейсов нет, `/kejsy/` показывает короткое сообщение и кнопку «Обсудить задачу», а не пустую сетку.
- Если у кейса нет необязательного факта, соответствующая строка не выводится.
- Если метрики скрыты, секция «Результат» показывает согласованный текстовый итог без числовых карточек.
- Если Featured Image отсутствует, используется fallback без предупреждения посетителю.
- Если официальный URL мероприятия недоступен, ссылка остаётся официальной; сайт не копирует форму регистрации и не обещает регистрацию на своей стороне.

## 12. Проверка и критерии приёмки

### Контент

- На `/kejsy/` ровно семь начальных кейсов без демонстрационных названий и цифр.
- У каждого кейса есть отдельный чистый URL, один `h1`, подтверждённые факты и CTA.
- Все метрики совпадают с материалами заказчика; неподтверждённые значения не добавлены.
- Виталина явно указана спикером мероприятия с подтверждённой должностью.
- Кнопка регистрации ведёт на официальную страницу «Коммерсанта».

### WordPress

- Тема активируется на чистом WordPress и создаёт семь `forma_case`.
- Повторная активация не создаёт восьмой дубликат.
- Изменение существующего кейса сохраняется после повторной активации и пересборки темы.
- Новый кейс, созданный в админке, появляется на `/kejsy/` и открывается по `/kejsy/{slug}/`.
- Изменение порядка меняет порядок карточек.
- Ранги 1–3 управляют тремя карточками на главной без дублирования.
- Шаги и метрики добавляются, удаляются и сохраняются без потери соседних полей.
- Slug `/kejsy/` не конфликтует с одиночными страницами CPT.

### Автоматические проверки

- JSON schema или эквивалентная проверка `content/cases.json`;
- тест генерации семи статических страниц и внутренних ссылок;
- тест полного набора title, canonical, Open Graph и JSON-LD;
- PHP syntax check;
- проверка WordPress bootstrap, повторной активации и сохранения правок;
- Playwright/E2E для архива, одной детальной страницы, новой записи из админки и мероприятия;
- responsive-проверка на 1280, 768, 360 и 320 px;
- проверка fixed header, burger, модального окна, Cookie-контролов и отсутствия горизонтального overflow;
- сборка нового `wordpress-theme/dist/forma-hotel.zip` только после прохождения всех проверок.

## 13. Что не входит в эту задачу

- ACF, Elementor, сторонний конструктор или обязательный плагин;
- раскрытие названий отелей без разрешения;
- самостоятельная проверка внутренних финансовых показателей у третьих лиц;
- полноценный динамический тип записи для мероприятий;
- импорт данных из внешнего API «Коммерсанта»;
- онлайн-регистрация на сайте Виталины;
- удаление текущей статической версии;
- публикация на production-сервере без отдельной команды пользователя.

## 14. Готовый результат

После реализации статический сайт содержит семь реальных кейсов и актуальное мероприятие. WordPress-тема после установки показывает тот же контент, а раздел «Кейсы» управляется из админки без внешних зависимостей. Новые записи автоматически используют единый архив, детальный шаблон, SEO-разметку и адаптивные правила сайта.
