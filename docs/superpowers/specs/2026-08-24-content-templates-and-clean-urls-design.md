# HTML-шаблоны контента и ЧПУ для будущего WordPress

## Цель

Подготовить демонстрационную HTML-версию сайта так, чтобы статьи, мероприятия, материалы и кейсы выглядели как записи, автоматически собранные из единых шаблонов. Структура должна без изменения дизайна переноситься в WordPress и использовать стабильные человекопонятные URL.

## Границы текущего этапа

- Реализуется статический HTML-прототип без PHP, базы данных и WordPress-админки.
- Для каждого типа контента создаётся один законченный пример детальной страницы.
- Карточки архивов ведут на чистые URL без расширения `.html`.
- Текущие цвета, типографика, компоненты, формы, cookie-логика и адаптивное поведение сохраняются.
- Реальные домен, даты мероприятий, цены, платёжные ссылки и непредоставленные результаты не выдумываются.
- Полноценная WordPress-тема и регистрация типов записей выполняются на следующем этапе переноса.

## Информационная архитектура

### Раздел «Полезное»

Единый архив объединяет три визуально различимых типа публикаций:

1. Статья.
2. Мероприятие.
3. Материал.

Чистые URL прототипа:

```text
/poleznoe/
/poleznoe/stati/kak-provesti-audit-prodazh-otelya/
/poleznoe/meropriyatiya/prodazhi-otelya-kak-sistema/
/poleznoe/materialy/chek-list-audita-prodazh/
```

### Раздел «Кейсы»

Кейсы остаются самостоятельным разделом с отдельным архивом и единым шаблоном публикации:

```text
/kejsy/
/kejsy/rost-pryamyh-prodazh/
```

Все новые URL используют нижний регистр, дефисы между словами и завершающий слэш. Даты, идентификаторы и расширения файлов в публичные URL не включаются.

## Архив «Полезное»

- Сохраняет текущую страницу и карточную сетку.
- Каждая карточка постоянно показывает тип публикации, заголовок, краткое описание и однозначную подсказку перехода.
- Статья ведёт на страницу статьи.
- Мероприятие ведёт на страницу мероприятия, а не в контакты.
- Материал ведёт на страницу материала, а не открывает форму непосредственно из карточки.
- Недоступность покупки или регистрации объясняется на детальной странице; карточка остаётся навигационной.
- Все карточки выравниваются по общей сетке и используют существующий hover/focus/touch-паттерн.

## Шаблон статьи

### Поля

- Заголовок.
- Краткое описание.
- Рубрика или метка.
- Дата публикации и дата обновления.
- Автор.
- Время чтения.
- Главное изображение и alt-текст.
- Содержание с якорями.
- Набор текстовых разделов с подзаголовками.
- Итог или практический чек-лист.
- Связанные материалы.
- Финальный призыв к консультации.

### Визуальная структура

Хлебные крошки → заголовок и метаданные → главное изображение → боковое содержание на широком экране → основной текст → связанные материалы → FAQ/CTA.

## Шаблон мероприятия

### Поля

- Статус: анонс, регистрация открыта, завершено.
- Заголовок и краткое описание.
- Дата, время и часовой пояс.
- Формат: онлайн или офлайн.
- Место или платформа.
- Спикер.
- Программа мероприятия.
- Условия участия.
- Ссылка регистрации.
- Главное изображение и alt-текст.
- Связанные статьи и материалы.

### Визуальная структура

Хлебные крошки → статус и заголовок → компактная панель даты/формата/места → описание → программа → информация о спикере → CTA регистрации или сообщение «Дата будет объявлена» → связанные публикации → FAQ.

Демонстрационный анонс не получает вымышленную дату и не содержит активную внешнюю регистрацию.

## Шаблон материала

### Поля

- Тип: чек-лист, методика или стандарт.
- Заголовок и краткое описание.
- Статус доступа: бесплатно, платно, готовится.
- Цена и валюта только при наличии реальной цены.
- Формат файла.
- Объём или количество страниц.
- Для кого предназначен материал.
- Что входит в материал.
- Превью обложки или разворота.
- Ссылка получения или покупки.
- Связанные статьи.

### Состояния действия

- Бесплатно: «Получить материал».
- Платно и подключена оплата: «Купить материал» с реальной ценой.
- Материал готовится: «Запросить материал», открывающая существующую модальную форму.

### Визуальная структура

Хлебные крошки → обложка и продающая информация → статус/формат/объём → состав → аудитория → превью → CTA → связанные публикации → FAQ.

## Шаблон кейса

### Поля

- Заголовок и краткое описание результата.
- Тип гостиничного объекта без выдуманного названия.
- Исходная ситуация.
- Задача.
- Диагностика.
- Выполненные решения и этапы внедрения.
- Подтверждённые результаты.
- Метрики только при разрешении на публикацию.
- Период работы.
- Режим конфиденциальности.
- Отзыв только при наличии согласованного текста.
- Связанные услуги.
- CTA обсуждения похожей задачи.

### Визуальная структура

Хлебные крошки → заголовок и итог → главное изображение → навигация по этапам → контекст → задача → работа → результат → связанные услуги → FAQ/CTA.

## Техническая SEO-основа

Для каждой индексируемой страницы предусматриваются:

- уникальные `title` и `meta description`, собранные из полей записи;
- абсолютный canonical с чистым URL на временном домене `example.ru`;
- Open Graph title, description, type, URL и image;
- хлебные крошки в HTML и `BreadcrumbList` JSON-LD;
- `Article` JSON-LD для статьи;
- `Event` JSON-LD только после заполнения реальной даты, формата и места;
- `Product` JSON-LD для материала только после появления реальной цены и возможности покупки;
- `CreativeWork` для опубликованного кейса;
- sitemap только с чистыми индексируемыми URL;
- внутренние ссылки только на чистые URL.

Подбор поисковых запросов и написание дополнительных SEO-текстов не входят в этот этап. Текущий этап даёт корректную техническую структуру, которую можно наполнить финальным контентом позже.

## Совместимость со старыми HTML-адресами

- Старые `blog.html`, `article.html`, `projects.html` и `project.html` не включаются в новый sitemap.
- Внутренние ссылки переводятся на чистые URL.
- Файлы временно сохраняются, чтобы не ломать локальную демонстрацию и существующие закладки.
- При переносе на WordPress для старых адресов настраиваются постоянные 301-редиректы на соответствующие чистые URL.

## Карта переноса в WordPress

### Типы записей

- Статья: стандартный тип `post`.
- Мероприятие: `forma_event`.
- Материал: `forma_material`.
- Кейс: `forma_case`.

### Шаблоны темы

```text
page-poleznoe.php
single.php
single-forma_event.php
single-forma_material.php
archive-forma_case.php
single-forma_case.php
```

Страница `page-poleznoe.php` собирает стандартные записи, мероприятия и материалы в единый архив. Отдельные публичные архивы мероприятий и материалов на первом WordPress-этапе не создаются. Поля прототипа сопоставляются с Gutenberg-блоками и зарегистрированными метаполями. Значения, влияющие на Event/Product JSON-LD, выводятся только после заполнения обязательных полей.

## Проверка

- Все чистые URL открываются на локальном сервере и возвращают HTTP 200.
- Карточки архивов ведут на правильный тип шаблона.
- На каждой детальной странице один `h1`, корректная иерархия заголовков, canonical и хлебные крошки.
- Sitemap содержит новые чистые URL и не содержит старые адреса контентных шаблонов.
- Все внутренние ссылки разрешаются без 404.
- JSON-LD парсится как валидный JSON и не содержит выдуманных обязательных данных.
- Страницы проверяются на десктопной и мобильной ширине без горизонтального скролла.
- Полный набор автоматических тестов проекта проходит без ошибок.
